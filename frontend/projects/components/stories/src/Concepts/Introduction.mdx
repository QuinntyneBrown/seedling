## Principles

- **The mocks are the source of truth.** `docs/mocks` is the design. Components carry the mocks' BEM classes verbatim,
  so one set of Playwright locators and visual baselines serves both the mocks and the app.
- **One primary action per screen.** The brand fill (`--colorBrandBackground`) marks the single next step; everything
  else is quiet.
- **State is ARIA.** Selection, pressed and invalid states are `aria-current`, `aria-pressed`, `aria-invalid` and
  `role="switch"`, never a class alone.
- **Phone first, full width later.** A bottom navigation below 720px, a sticky top bar above it, wider layouts from
  1024px.
- **Every component is split across files.** `<name>.ts`, `<name>.html`, `<name>.scss`; no inline templates or styles.

## Where the code lives

| Path                                           | Purpose                                                         |
| ---------------------------------------------- | --------------------------------------------------------------- |
| `frontend/projects/components/src/lib/`        | Component source (`<name>/<name>.ts`, `.html`, `.scss`)         |
| `frontend/projects/components/src/lib/styles/` | Tokens, breakpoints and global chrome                           |
| `frontend/projects/components/src/lib/tokens/` | The TypeScript theme the tokens are generated from              |
| `frontend/projects/components/stories/src/`    | This Storybook: concept and theme MDX, one folder per component |
| `frontend/projects/components/.storybook/`     | Storybook configuration, manager theme and branding             |
