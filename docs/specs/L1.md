# L1 - High-Level Requirements

> Each L1 names a capability the Seedling system shall deliver. Detailed, testable behaviours live in
> `L2.md`. Number in order; never renumber. Revise in place and date the revision.

## L1-001: Authentication and Account Lifecycle
The system shall let a person register, sign in, sign out, recover a forgotten password, reset it
via an emailed link, and verify ownership of their email address. Sessions shall persist across
page reloads when the user opts in, and shall be revocable.

## L1-002: Responsive Progressive Web Experience
Every user-facing page shall render usably from 320 px through 1920 px, be installable as a
progressive web app, and keep cached routes usable offline.

## L1-003: Administration
An administrator shall operate the platform from a separate administration application on its
own host, sharing the sign-in and the design system with the main application.

## L1-004: Agents on Azure
Agent-backed features shall run on Claude in Microsoft Foundry through the API's managed identity,
be bounded by per-run caps, a daily run cap and a monthly spend cap, and fall back with a notice
when the agents are off, fail or run over budget.

## L1-005: Security
The system shall protect credentials and session tokens, enforce authorization on all non-public
endpoints, scope every tenant-owned resource to its tenant, validate every external input, defend
against the OWASP Top 10, and never log secrets or personally identifying information in plaintext.

## L1-006: Operations
The system shall provision its own Azure stack from source on every push to `main`, apply database
migrations explicitly from the pipeline, and expose logs and traces in Application Insights.
