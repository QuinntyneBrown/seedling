# L2 - Detailed Requirements

> Each L2 traces to exactly one L1 requirement in `L1.md`. Acceptance criteria use Given/When/Then
> so they translate directly to tests. Every acceptance test in this repository shall carry a
> `Traces to: L2-NNN` header comment. Number in order; never renumber.
>
> Revised 2026-10-29: the previous requirements set was replaced by the Seedlings RESP requirements.
>
> Responsive tiers used below: extra small (< 576 px, from 320 px), small (>= 576 px), medium
> (>= 768 px), large (>= 992 px) and extra large (>= 1200 px, through 1920 px and wider).

---

## L2-001: Web app manifest
**Traces to:** L1-001

The app shall ship a web app manifest with name, short name, icons at 192 px and 512 px (including
a maskable icon), start URL, `display: standalone` and a theme colour.

**Acceptance Criteria:**
1. Given a user opens Seedlings in Chrome on Android, when the page loads, then the browser shall
   offer an install prompt.
2. Given a user opens Seedlings in Safari on iOS, when they choose Add to Home Screen, then the app
   shall launch full-screen with the Seedlings icon and no browser chrome.
3. Given a user opens Seedlings in Edge on Windows or Chrome on macOS, when the page loads, then the
   browser shall offer to install the app.

---

## L2-002: Service worker shell caching and updates
**Traces to:** L1-001

The service worker shall precache the app shell and serve it when the network is unavailable, and
shall detect and offer new versions.

**Acceptance Criteria:**
1. Given the app has been opened once online, when the device is offline and the user opens it,
   then the app shell shall load from the cache.
2. Given a new version is deployed, when the user next opens the app online, then the new shell
   shall be fetched and the user shall be prompted to reload.
3. Given the user dismisses the reload prompt, when they next open the app, then the new version
   shall be active.

---

## L2-003: Offline status and queue
**Traces to:** L1-003

The last known case status shall be shown offline, and form inputs and document uploads made
offline shall be queued locally and submitted automatically on reconnect.

**Acceptance Criteria:**
1. Given the app has been opened once online, when the device is offline and the user opens it, then
   the last known status of each case shall be shown within 2 seconds, labelled with the time it was
   last updated.
2. Given the user is offline, when they complete an intake step, then the step shall be saved locally
   and marked "Will send when online".
3. Given queued items exist, when connectivity returns, then they shall be submitted in the order
   they were made and the status shall update without user action.
4. Given a queued upload fails on submission, when the failure is detected, then the user shall be
   told which item failed and why, and shall be able to retry it.
5. Given the user signs out while items are queued, when sign-out completes, then the queued items
   and all locally stored personal data shall be removed from the device.

---

## L2-004: Breakpoints
**Traces to:** L1-002

Layouts shall adapt at the extra small, small, medium, large and extra large tiers with no
horizontal scroll at any width from 320 px.

**Acceptance Criteria:**
1. Given a viewport width of 320 px, when any screen is displayed, then all content shall fit
   without horizontal scrolling and every control shall be reachable.
2. Given a viewport width below 768 px, when the dashboard is displayed, then the cases shall be
   shown in a single column.
3. Given a viewport width of 992 px or more, when the dashboard is displayed, then the cases shall be
   shown in at least two columns.
4. Given a viewport width of 1920 px, when the dashboard is displayed, then the content shall be
   constrained to a centred column at most 1200 px wide.
5. Given the device rotates between portrait and landscape, when the layout reflows, then no
   in-progress input shall be lost.

---

## L2-005: Touch and pointer targets
**Traces to:** L1-002

Every tappable control shall be at least 44 by 44 px on touch devices.

**Acceptance Criteria:**
1. Given a viewport width below 576 px with touch input, when any screen renders, then no
   interactive control shall measure under 44 by 44 px.
2. Given two adjacent interactive controls, when they render on a touch device, then their target
   areas shall not overlap.

---

## L2-006: Performance budget
**Traces to:** L1-004

The initial JavaScript bundle shall be under 300 KB gzipped, and the app shall be interactive within
4 seconds on a mid-range Android phone over 4G.

**Acceptance Criteria:**
1. Given a production build, when the bundle size is measured, then the initial JavaScript shall be
   under 300 KB gzipped and the build shall fail if it is not.
2. Given a cold load with Lighthouse mobile emulation (Moto G Power, simulated 4G throttling), when
   Lighthouse runs against the dashboard, then Time to Interactive shall be 4 seconds or less and the
   performance score shall be 80 or higher.

---

## L2-007: Sign-up and verification
**Traces to:** L1-005

A parent shall sign up with an email address or a mobile number and verify it with a one-time code.

**Acceptance Criteria:**
1. Given a new parent enters an email address, when they submit, then a 6-digit code shall be sent
   and the account shall be created only after the code is entered within 10 minutes.
2. Given a parent enters a mobile number, when they submit, then the same flow shall run by SMS.
3. Given a wrong code is entered 5 times, when the fifth attempt fails, then the code shall be
   invalidated and a new one shall be required.
4. Given a code older than 10 minutes, when it is entered, then it shall be rejected with the message
   that the code has expired and an option to send a new one.
5. Given an email address or mobile number in an invalid format, when the parent submits, then no
   code shall be sent and the field shall show a plain-language error.

---

## L2-008: Multi-device sign-in
**Traces to:** L1-005

A signed-in parent shall see the same cases and progress on any device.

**Acceptance Criteria:**
1. Given a parent completed two intake steps on a phone, when they sign in on a laptop, then the
   intake shall resume at step three.
2. Given a parent is signed in on two devices, when they change a case on one, then the other shall
   show the change the next time the case is loaded.

---

## L2-009: Child profiles
**Traces to:** L1-005

A parent shall add a child with first name, last name, date of birth and relationship, creating one
case per child.

**Acceptance Criteria:**
1. Given a parent has one child, when they add a second, then a second case shall appear on the
   dashboard with its own status.
2. Given a child is added with a date of birth that makes them 18 or older, when the parent saves,
   then Seedlings shall explain the child is outside RESP grant eligibility and shall not open a case.
3. Given a date of birth in the future, when the parent saves, then the child shall not be saved and
   the field shall show a plain-language error.

---

## L2-010: Consent capture
**Traces to:** L1-006

Before each category of sensitive data (identity documents, SINs, financial information) is
requested, the parent shall see why it is needed and give consent with a single control.

**Acceptance Criteria:**
1. Given the intake reaches the SIN step, when the screen opens, then a plain-language explanation of
   why the SIN is required shall be shown with a single consent control, and the input shall be
   disabled until consent is given.
2. Given consent is given, when the case is viewed later, then the consent and its timestamp shall
   appear in the case audit trail.
3. Given consent has not been given, when a request to store that category of data reaches the API,
   then it shall be rejected and nothing shall be stored.

---

## L2-011: Eligibility questions
**Traces to:** L1-007

The eligibility check shall ask at most 6 questions: the child's birth year, the parent's province,
the household's approximate adjusted net income band, the number of children, Canada Child Benefit
status, and whether an RESP already exists.

**Acceptance Criteria:**
1. Given a parent starts the check, when they answer all questions, then the result shall be shown
   within 3 seconds.
2. Given the child was born in 2004 or later and the household income is at or below the CLB
   threshold for its number of children, when the result is shown, then it shall state that the child
   qualifies for the Canada Learning Bond and show the estimated amount in dollars.
3. Given the household income is above the CLB threshold, when the result is shown, then it shall
   state that the child does not qualify for the bond but does qualify for the 20% CESG, with an
   example dollar amount.
4. Given any question is unanswered, when the parent asks for the result, then the unanswered
   question shall be highlighted and no result shall be shown.

---

## L2-012: Amount before documents
**Traces to:** L1-007

No document or SIN shall be requested until the eligibility result has been shown.

**Acceptance Criteria:**
1. Given a parent has not completed the eligibility check, when they try to open the document step,
   then they shall be returned to the check.
2. Given a parent has not completed the eligibility check, when a document upload or SIN reaches the
   API for that case, then it shall be rejected and nothing shall be stored.

---

## L2-013: Intake autosave
**Traces to:** L1-008

Every intake field shall save on change.

**Acceptance Criteria:**
1. Given a parent types an address and closes the app, when they reopen it, then the address shall be
   present.
2. Given a field has been changed, when it is saved, then a "Saved" indicator shall be shown within
   1 second while online.

---

## L2-014: Intake steps
**Traces to:** L1-008

The intake shall collect, in order: parent identity, parent address, child identity, child SIN,
parent SIN, existing RESP details if any, and preferred contact channel.

**Acceptance Criteria:**
1. Given a parent is on any step, when they view the screen, then a progress indicator shall show the
   step number and the total number of steps.
2. Given a required field is empty, when the parent taps Next, then the field shall be highlighted
   with a plain-language message naming what is missing and the step shall not advance.
3. Given the parent answered that no RESP exists, when they finish the parent SIN step, then the
   existing RESP details step shall be skipped.

---

## L2-015: Camera capture
**Traces to:** L1-009

Documents shall be captured through the device camera or the file picker.

**Acceptance Criteria:**
1. Given the birth certificate step, when the parent taps Take photo, then the camera shall open with
   a frame guide and the captured image shall be previewed before saving.
2. Given the parent taps Upload a file, when they choose a file, then the file picker shall accept
   JPEG, PNG, HEIC and PDF files.
3. Given the parent has denied camera permission, when they tap Take photo, then they shall be told
   how to allow it and offered Upload a file instead.

---

## L2-016: Image quality check
**Traces to:** L1-009

Each captured image shall be checked for blur, glare and cropping before it is saved.

**Acceptance Criteria:**
1. Given an image is blurred so that its text is unreadable, when it is captured, then the parent
   shall be asked to retake it with the reason stated.
2. Given an image with glare covering text or a document edge cut off, when it is captured, then the
   parent shall be asked to retake it with the reason stated.
3. Given an image passes, when it is saved, then it shall be encrypted and the step shall show a green
   check.

---

## L2-017: Provider selection
**Traces to:** L1-010

The agent shall pick a provider from the rules base that charges no account fees, accepts CLB-only
accounts with zero contribution, and serves the parent's province.

**Acceptance Criteria:**
1. Given intake is complete, when the agent runs provider selection, then exactly one recommended
   provider shall be shown with a reason of at most two sentences and a link to the provider's fee
   page.
2. Given no provider in the rules base matches, when selection runs, then the case shall be routed to
   human review.

---

## L2-018: Form pre-fill
**Traces to:** L1-010

The agent shall pre-fill the provider's RESP application and ESDC form SDE 0093 from intake data.

**Acceptance Criteria:**
1. Given intake is complete, when the parent opens the review screen, then every field on both forms
   that intake data covers shall be populated, and any field the agent could not fill shall be listed
   at the top.
2. Given the parent edits a pre-filled field, when they save, then the edited value shall be used in
   the submission.

---

## L2-019: Submission tracking
**Traces to:** L1-010

The agent shall record each submission and track it until the provider confirms it.

**Acceptance Criteria:**
1. Given an application is submitted, when the provider confirms the account number, then the case
   status shall move to Account open and the account number shall be stored.
2. Given 15 business days pass with no confirmation, when the daily check runs, then the case shall
   be flagged and the parent shall be told the agent is following up.

---

## L2-020: Approval gate
**Traces to:** L1-011

No submission, account opening or third-party data share shall occur without a recorded parent
approval.

**Acceptance Criteria:**
1. Given the forms are pre-filled, when the parent has not tapped Approve and submit, then no data
   shall leave Seedlings.
2. Given the parent taps Approve and submit, when the action completes, then the approval shall be
   logged with its timestamp and the exact data shared.
3. Given the parent taps Decline, when the action completes, then the case shall pause and the parent
   shall be able to edit the forms.
4. Given the data changes after approval, when a submission is attempted, then it shall be blocked
   until the parent approves again.

---

## L2-021: Status dashboard
**Traces to:** L1-012

Each case shall show exactly one of: Checking eligibility, Collecting documents, Ready to approve,
Submitted, Account open, Bond claimed, Needs attention, Complete.

**Acceptance Criteria:**
1. Given any case, when the dashboard loads, then its status, a one-sentence explanation and the next
   action for the parent shall be shown.
2. Given a case's status is Needs attention, when the parent opens the case, then the specific item
   needed shall be shown first.
3. Given a case's status is Submitted, when the dashboard loads, then the next action shall state that
   nothing is needed from the parent.

---

## L2-022: Human handoff
**Traces to:** L1-013

When the agent cannot complete a step, the case shall enter a review queue and the parent shall be
told.

**Acceptance Criteria:**
1. Given a provider rejects a document, when the rejection is received, then the case shall be queued
   for review and the parent shall see "A person is checking this" with the expected response time.
2. Given a reviewer resolves the issue, when they return the case, then the agent shall resume from
   the failed step.

---

## L2-023: Deposit confirmation
**Traces to:** L1-014

Seedlings shall record expected CLB and CESG deposits and confirm them when they arrive.

**Acceptance Criteria:**
1. Given the account is open and the bond was claimed, when the provider reports the CLB deposit, then
   the case shall show the amount and the date.
2. Given 90 days pass after the claim with no deposit, when the daily check runs, then the parent shall
   be alerted and the case shall enter review.

---

## L2-024: Contribution room reminder
**Traces to:** L1-014

Once per calendar year Seedlings shall tell the parent the CESG room remaining and the grant it would
earn, without pressure to contribute.

**Acceptance Criteria:**
1. Given a parent has contributed $0 this year, when the annual reminder is sent, then it shall state
   the remaining room and the matching grant, and shall include a one-tap "Not this year" option.
2. Given the parent taps "Not this year", when further reminders for that year are due, then none
   shall be sent.
3. Given a parent has already been sent the annual reminder, when the same calendar year continues,
   then no second reminder shall be sent.

---

## L2-025: Life change reporting
**Traces to:** L1-015

The parent shall report an address change, new child, custody change or income change from the case
screen.

**Acceptance Criteria:**
1. Given a parent reports an address change, when they save, then the case shall store the new
   address and the agent shall queue a provider update for approval.
2. Given a parent reports an income change that moves them into the CLB range, when they save, then
   the agent shall re-run eligibility and, if the child is newly eligible, start a bond claim for
   approval.
3. Given a parent reports a new child, when they save, then the child-profile flow in L2-009 shall
   open.
4. Given a parent reports a custody change, when they save, then the case shall be routed to human
   review.

---

## L2-026: Notification channels
**Traces to:** L1-016

The parent shall choose push, SMS or email for notifications.

**Acceptance Criteria:**
1. Given the parent chose SMS, when a case changes to Ready to approve, then an SMS with a deep link
   to that case shall be sent within 1 minute.
2. Given the parent chose push and has denied browser notification permission, when a notification is
   due, then it shall be sent by email instead.
3. Given a deep link is opened by a signed-out user, when it loads, then sign-in shall be required
   before the case is shown.

---

## L2-027: Language switch
**Traces to:** L1-017

All parent-facing text shall be available in English and French, selectable in settings and
defaulting to the browser language.

**Acceptance Criteria:**
1. Given a browser language of fr-CA, when the app loads for the first time, then all screens shall
   render in French.
2. Given a browser language that is neither English nor French, when the app loads for the first time,
   then all screens shall render in English.
3. Given the parent switches language, when the change is saved, then every screen, notification and
   generated document shall use the new language.

---

## L2-028: Reading level
**Traces to:** L1-017

All parent-facing copy shall test at Grade 6 or below.

**Acceptance Criteria:**
1. Given the English and French string files, when they are run through a readability check in the
   build pipeline, then the build shall fail if any string exceeds Grade 6.

---

## L2-029: Plan selection
**Traces to:** L1-018

The parent shall choose the free tier, the one-time launch fee or the annual plan before submission.

**Acceptance Criteria:**
1. Given the parent is on the plan screen, when the free tier is available for their provider, then it
   shall be shown first with the price $0.
2. Given the parent selects the launch fee, when they tap Pay, then a hosted checkout shall open and
   Seedlings shall never receive the card number.

---

## L2-030: Payment confirmation
**Traces to:** L1-018

A successful payment shall unlock submission.

**Acceptance Criteria:**
1. Given the checkout succeeds, when the payment provider's signed webhook is received, then the case
   shall show Paid and the Approve and submit control shall be enabled.
2. Given the checkout fails, when the parent returns, then the plan screen shall be shown with the
   failure reason and no charge recorded.
3. Given a webhook with an invalid signature, when it is received, then it shall be rejected and the
   case shall not change.
4. Given the same webhook is delivered twice, when the second arrives, then the payment shall be
   recorded once.

---

## L2-031: Encryption
**Traces to:** L1-019

All traffic shall use TLS 1.2 or higher and all stored personal data shall be encrypted at rest.

**Acceptance Criteria:**
1. Given any request made over plain HTTP, when it is received, then it shall be redirected to HTTPS.
2. Given any response, when it is returned, then it shall carry a `Strict-Transport-Security` header.
3. Given a TLS 1.0 or 1.1 client, when it connects, then the connection shall be refused.

---

## L2-032: Sensitive data vault
**Traces to:** L1-019

SINs and identity documents shall be stored in a separate store with per-access logging and shown
only after re-authentication.

**Acceptance Criteria:**
1. Given a signed-in parent opens the SIN field, when more than 5 minutes have passed since they last
   authenticated, then they shall be asked to re-authenticate before it is shown.
2. Given any read of the vault, when it occurs, then an entry with the user, the purpose and the
   timestamp shall be written to the access log.
3. Given a stored SIN, when it is shown outside the re-authenticated view, then only its last 3 digits
   shall be visible.

---

## L2-033: Document deletion
**Traces to:** L1-019

Identity documents shall be deleted 30 days after the provider confirms the account is open unless
the parent opts to keep them.

**Acceptance Criteria:**
1. Given the account is confirmed open, when 30 days pass, then the documents shall be deleted and the
   parent shall be notified.
2. Given the parent chose Keep for another child, when 30 days pass, then the documents shall be
   retained and the choice shall be logged.

---

## L2-034: Data access and deletion
**Traces to:** L1-020

The parent shall view, export and delete their data from settings.

**Acceptance Criteria:**
1. Given a parent taps Export my data, when the export is ready, then a downloadable JSON file shall
   be provided within 24 hours.
2. Given a parent taps Delete my account, when they confirm, then all personal data shall be deleted
   within 30 days and a confirmation shall be sent.
3. Given a parent taps Export my data or Delete my account, when more than 5 minutes have passed since
   they last authenticated, then they shall be asked to re-authenticate first.

---

## L2-035: Audit trail
**Traces to:** L1-020

Every agent action, parent approval and third-party submission shall be logged and visible to the
parent.

**Acceptance Criteria:**
1. Given a case, when the parent opens Activity, then a dated list of every action shall be shown,
   newest first, including what data was sent and to whom.
2. Given an audit entry, when any user attempts to change or delete it through the API, then the
   attempt shall be rejected.

---

## L2-036: Wizard entry and time estimate
**Traces to:** L1-021

Immediately after verification, the wizard shall open with a welcome screen stating what Seedlings
will do, the total number of steps and the total expected time in minutes.

**Acceptance Criteria:**
1. Given a parent has just verified their account, when the next screen loads, then it shall show the
   step count, the expected total time (for example "About 20 minutes") and a single Start button.
2. Given the parent has two children to add, when the estimate is shown, then it shall include the
   per-child steps for both children.

---

## L2-037: One question per screen
**Traces to:** L1-021

Each wizard screen shall ask exactly one question or request exactly one item, with one primary
action.

**Acceptance Criteria:**
1. Given any wizard screen, when it renders, then it shall contain one prompt, one input or choice,
   one Next or Continue control and a Back control.
2. Given any wizard screen, when its text is counted, then the prompt and any helper text shall total
   no more than 40 words.

---

## L2-038: Persistent roadmap
**Traces to:** L1-021

Every wizard screen shall show a roadmap of all steps with the current step highlighted, completed
steps marked and upcoming steps visible.

**Acceptance Criteria:**
1. Given the parent is on step 4 of 12, when the screen renders, then the roadmap shall show steps 1
   to 3 as done, step 4 as current (`aria-current="step"`), and steps 5 to 12 as upcoming with their
   names.
2. Given a viewport width below 576 px, when the roadmap renders, then it shall collapse to a progress
   bar with the step label and expand to the full list on tap.
3. Given a viewport width of 992 px or more, when the roadmap renders, then it shall be shown as a
   persistent side panel beside the question.
4. Given a completed step is tapped in the roadmap, when the tap is handled, then the parent shall be
   taken to that step to review or change their answer.
5. Given an upcoming step is tapped in the roadmap, when the tap is handled, then the parent shall stay
   on the current step.

---

## L2-039: Time spent and time remaining
**Traces to:** L1-021

The roadmap shall show the time spent so far and the estimated time remaining, updated at each step.

**Acceptance Criteria:**
1. Given a parent has completed three steps in 3 minutes of a 20-minute estimate, when they reach
   step 4, then the roadmap shall show "3 minutes in, about 17 minutes left".
2. Given the parent is faster or slower than the estimate, when the remaining time is recalculated,
   then it shall be the sum of the remaining steps' standard estimates, not a projection of the
   parent's pace.

---

## L2-040: Stop and resume
**Traces to:** L1-021

The parent shall be able to leave the wizard at any step and resume at the same step on any device.

**Acceptance Criteria:**
1. Given a parent closes the app on step 6, when they return the next day on another device, then
   the wizard shall open on step 6 with earlier answers intact and the roadmap showing time remaining.
2. Given a parent leaves mid-wizard, when 24 hours pass without their return, then exactly one
   reminder shall be sent through their chosen channel stating the time left to finish.

---

## L2-041: Wizard steps
**Traces to:** L1-021

The wizard shall cover, in order: language, parent name, child or children, eligibility questions,
eligibility result, contact preference and consent, then hand off to the intake steps in L2-014
within the same roadmap.

**Acceptance Criteria:**
1. Given a parent completes the wizard's setup steps, when they reach the eligibility result, then the
   roadmap shall extend to show the remaining intake and document steps as part of the same journey.
2. Given the last step completes, when the parent taps Finish, then they shall land on the dashboard
   with the child's case in Ready to approve or Collecting documents status and a short "You're all
   set" message.

---

## L2-042: Plain language and no jargon
**Traces to:** L1-021

Wizard copy shall use no acronym without its expansion on first use and no financial term without a
one-line explanation.

**Acceptance Criteria:**
1. Given the term CLB appears, when it is first shown, then it shall be written as "Canada Learning
   Bond (CLB), free money from the government for your child's education".
2. Given the term RESP appears, when it is first shown, then it shall be written with its expansion,
   Registered Education Savings Plan, and a one-line explanation.

---

## L2-043: Verification code abuse protection
**Traces to:** L1-005

Sending and checking one-time codes shall be rate limited and shall not reveal whether an account
exists.

**Acceptance Criteria:**
1. Given 3 codes have been requested for the same email address or mobile number within one hour,
   when a fourth is requested, then the API shall respond 429 and no code shall be sent.
2. Given an email address that already has an account, when sign-up is submitted, then the response
   shall be identical to the response for a new address.
3. Given 20 code requests from one IP address within one hour, when another is made, then the API
   shall respond 429.

---

## L2-044: Session lifecycle
**Traces to:** L1-005

Sessions shall use short-lived access tokens with rotating refresh tokens, and shall be revocable.

**Acceptance Criteria:**
1. Given a signed-in parent, when their access token expires, then the app shall renew it with the
   refresh token without interrupting the parent.
2. Given a refresh token that has already been used, when it is presented again, then it shall be
   rejected and every session in its family shall be revoked.
3. Given a parent taps Sign out of all devices, when the action completes, then every other device
   shall be signed out at its next request.

---

## L2-045: Case authorization
**Traces to:** L1-019

Every endpoint except sign-up, sign-in, code verification and the payment webhook shall require
authentication, and a parent shall reach only their own cases, children and documents.

**Acceptance Criteria:**
1. Given a request without a valid access token, when it reaches a protected endpoint, then the API
   shall respond 401.
2. Given parent A is signed in, when they request a case, child or document belonging to parent B,
   then the API shall respond 404 and no data shall be returned.
3. Given a human reviewer, when they open a case in the review queue, then the vault read shall be
   recorded in the access log with the reviewer and the purpose.

---

## L2-046: Input validation
**Traces to:** L1-019

Every input shall be validated on the server, whatever the client has already checked.

**Acceptance Criteria:**
1. Given a SIN that fails the Luhn check or is not 9 digits, when it is submitted, then the API shall
   respond 400 with a field error and nothing shall be stored.
2. Given a postal code that does not match the Canadian format, when it is submitted, then the API
   shall respond 400 with a field error.
3. Given an upload that is larger than 10 MB, or whose content is not JPEG, PNG, HEIC or PDF whatever
   its file extension, when it is submitted, then it shall be rejected and nothing shall be stored.
4. Given text input containing HTML or script, when it is later displayed, then it shall be rendered
   as text and not executed.

---

## L2-047: No personal data in logs
**Traces to:** L1-019

No SIN, one-time code, token, card detail or document content shall be written to application logs
or telemetry.

**Acceptance Criteria:**
1. Given a request carrying a SIN or a one-time code, when it is logged, then the log entry shall
   contain neither value.
2. Given an unhandled error while processing a SIN, when the error is logged, then the log entry shall
   not contain the SIN.

---

## L2-048: API response time
**Traces to:** L1-004

Parent-facing API reads shall be fast under expected load.

**Acceptance Criteria:**
1. Given 50 concurrent signed-in parents, when they load the dashboard repeatedly for 5 minutes, then
   the 95th-percentile response time for the case list shall be under 500 ms.
2. Given an intake field is saved, when the API handles the save, then the 95th-percentile response

## L2-049: Accessible screens
**Traces to:** L1-022

Every parent-facing screen shall meet WCAG 2.2 Level AA.

**Acceptance Criteria:**
1. Given any screen, when an automated accessibility scan runs, then it shall report no WCAG 2.2 A or
   AA violations.
2. Given any screen, when it is operated with the keyboard alone, then every control shall be
   reachable and operable with a visible focus indicator.
3. Given any form field with an error, when the error is shown, then the field shall have
   `aria-invalid="true"` and the message shall be announced to screen readers.
4. Given text zoomed to 200%, when any screen is displayed at 320 px, then no content shall be lost or
   overlap.
